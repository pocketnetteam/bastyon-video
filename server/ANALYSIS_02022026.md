# Анализ ошибок от 01.02.2026 и связь с очередью video-transcoding

## Резюме

Анализ лог-файла `02022026.log` показывает **прямую связь** между ошибками и образовавшейся очередью на JOB `video-transcoding`. Обнаружено несколько критических проблем, которые усугубляли друг друга и привели к перегрузке системы.

## Статистика ошибок

- **775 ошибок** `SequelizeConnectionAcquireTimeoutError` - таймауты при получении соединений с БД
- **42 ошибки** `Missing lock for job` в очереди `video-transcoding` - потеря блокировок задач
- **Множественные ошибки** с `@jimp/core` - некорректная обработка Promise
- **Ошибки ffmpeg** - сбои конвертации видео
- **Ошибки генерации изображений** - попытки создать скриншоты из аудио файлов (.mp3)

## Анализ проблем

### 1. Критическая проблема: Перегрузка пула соединений БД

**Проблема:**
- 775 ошибок `SequelizeConnectionAcquireTimeoutError` указывают на то, что пул соединений PostgreSQL был исчерпан
- В конфигурации Sequelize (`initializers/database.ts`) отсутствуют важные параметры:
  - `acquire` - таймаут получения соединения (по умолчанию 60000 мс)
  - `idle` - таймаут простоя соединения
  - `evict` - интервал проверки неактивных соединений

**Связь с очередью:**
- Каждая задача транскодинга выполняет множество запросов к БД (загрузка видео, обновление статусов, сохранение метаданных)
- При большом количестве параллельных задач транскодинга все соединения из пула заняты
- Другие компоненты системы (API запросы, планировщики) не могут получить соединение → таймауты
- Это создает каскадный эффект: ошибки БД → задачи не завершаются → очередь растет

### 2. Проблема с блокировками Bull Queue

**Проблема:**
- 42 ошибки `Missing lock for job` возникают когда:
  - Задача выполняется слишком долго (транскодинг может занимать часы)
  - Процесс перезапускается или падает
  - Redis теряет блокировку задачи
  - Задача пытается завершиться, но блокировка уже истекла

**Связь с очередью:**
- При потере блокировки задача не может корректно завершиться
- Задача остается в состоянии "active" или переходит в "failed"
- Накопление таких задач приводит к росту очереди
- Текущая настройка `maxStalledCount: 10` может быть недостаточной

### 3. Ошибка с @jimp/core

**Проблема:**
В файле `helpers/image-utils.ts` (строки 69-71):
```typescript
await jimpInstance
  .quality(95)
  .writeAsync(destination)
```

**Ошибка:** `TypeError: The "chunk" argument must be of type string or an instance of Buffer or Uint8Array. Received an instance of Promise`

**Причина:**
- Метод `writeAsync` в некоторых версиях Jimp может возвращать Promise, который не обрабатывается корректно
- Возможно, проблема в цепочке вызовов или версии библиотеки

**Связь с очередью:**
- Ошибка приводит к падению процесса обработки изображений
- Это может прервать задачу транскодинга, которая генерирует превью
- Прерванные задачи накапливаются в очереди

### 4. Ошибки ffmpeg

**Проблема:**
- Ошибка `Conversion failed!` с кодом 69
- Большое количество дублированных кадров (`dup=77345 drop=27598`)
- Указывает на проблемы с исходным видео или нехваткой ресурсов

**Связь с очередью:**
- Неудачные задачи транскодинга остаются в очереди
- При большом количестве таких задач очередь растет

### 5. Попытки генерации изображений из аудио файлов

**Проблема:**
- Ошибки `No video stream in input, cannot take screenshots` для `.mp3` файлов
- Система пытается создать скриншоты из аудио файлов

**Связь с очередью:**
- Эти ошибки не критичны, но создают дополнительную нагрузку
- Могут замедлять обработку других задач

### 3. Исправление ошибки с @jimp

**Файл:** `helpers/image-utils.ts`

Исправить обработку изображений:

```typescript
async function jimpProcessor (path: string, destination: string, newSize: { width: number, height: number }, inputExt: string) {
  let jimpInstance: Jimp
  const inputBuffer = await readFile(path)

  try {
    jimpInstance = await read(inputBuffer)
  } catch (err) {
    logger.debug('Cannot read %s with jimp. Try to convert the image using ffmpeg first.', path, { err })

    const newName = path + '.jpg'
    await convertWebPToJPG(path, newName)
    await rename(newName, path)

    jimpInstance = await read(path)
  }

  await remove(destination)

  // Optimization if the source file has the appropriate size
  const outputExt = getLowercaseExtension(destination)
  if (skipProcessing({ jimpInstance, newSize, imageBytes: inputBuffer.byteLength, inputExt, outputExt })) {
    return copy(path, destination)
  }

  // ИСПРАВЛЕНИЕ: Правильная обработка resize и writeAsync
  jimpInstance = jimpInstance.resize(newSize.width, newSize.height)
  
  // Убедиться, что writeAsync правильно обрабатывается
  const result = await jimpInstance.quality(95).writeAsync(destination)
  
  // Если writeAsync возвращает Promise, дождаться его
  if (result && typeof result.then === 'function') {
    await result
  }
}
```

**Альтернативное решение:** Обновить версию `jimp` до последней стабильной.

### 4. Улучшение обработки ошибок транскодинга

**Файл:** `lib/job-queue/handlers/video-transcoding.ts`

Добавить более детальную обработку ошибок:

```typescript
async function processVideoTranscoding (job: Job) {
  const payload = job.data as VideoTranscodingPayload
  logger.info('Processing transcoding job %d.', job.id, lTags(payload.videoUUID))

  try {
    const video = await VideoModel.loadAndPopulateAccountAndServerAndTags(payload.videoUUID)
    // No video, maybe deleted?
    if (!video) {
      logger.info('Do not process job %d, video does not exist.', job.id, lTags(payload.videoUUID))
      return undefined
    }

    const user = await UserModel.loadByChannelActorId(video.VideoChannel.actorId)

    const handler = handlers[payload.type]

    if (!handler) {
      throw new Error('Cannot find transcoding handler for ' + payload.type)
    }

    await handler(job, payload, video, user)

    return video
  } catch (err) {
    // Логировать детальную информацию об ошибке
    logger.error('Error processing transcoding job %d', job.id, { 
      err, 
      payload,
      jobProgress: job.progress(),
      jobAttemptsMade: job.attemptsMade
    })
    
    // Если это ошибка БД, не перебрасывать исключение, чтобы задача не застряла
    if (err.name === 'SequelizeConnectionAcquireTimeoutError') {
      logger.warn('Database connection timeout for job %d, will retry', job.id)
      throw err // Bull автоматически повторит задачу
    }
    
    throw err
  }
}
```

## Вывод

Ошибки **напрямую связаны** с образовавшейся очередью на `video-transcoding`. Основная причина - перегрузка пула соединений БД из-за большого количества параллельных задач транскодинга. Это создало каскадный эффект:
- Задачи транскодинга не могут получить соединение с БД → таймауты
- Задачи не завершаются → накапливаются в очереди
- Очередь растет → еще больше задач пытаются получить соединение
- Цикл повторяется

Исправление конфигурации пула БД и оптимизация очередей должны решить основную проблему.
